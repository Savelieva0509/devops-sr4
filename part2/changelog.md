# Завдання 2.4. Навіщо CHANGELOG у DevOps

- Видно, що саме змінилось у кожній версії, — без читання всіх комітів.
- Перед деплоєм команда розуміє ризики: нові функції (Added), виправлення (Fixed), безпека (Security).
- Легко відкотитись: якщо після релізу 0.2.0 щось зламалось, з changelog зрозуміло, до якої версії повертатись і чому.
- CI/CD може брати опис релізу з CHANGELOG (GitHub Releases, нотатки до деплою).
- Зв'язок з версіями пакета: 0.1.0 у CHANGELOG = version у pyproject.toml = файл у devpi.
